# Architecture Decision Records (ADRs)

An ADR captures one significant architecture decision and why it was made.

## When to create one
- Architecture style
- Database or storage choice
- Queue or event-broker choice
- AI provider/model strategy
- RAG/vector storage choice
- Authentication or authorization design
- Deployment, availability or data-retention strategy
- A major migration or service extraction

## Naming
Use sequential numbers and concise titles, for example:
- `ADR-0001-modular-monolith.md`
- `ADR-0002-relational-database.md`
- `ADR-0003-ai-provider-adapter.md`

Use `ADR-TEMPLATE.md` for new records. An ADR records the decision at that time; if it changes, create a new ADR and link the superseded one.
